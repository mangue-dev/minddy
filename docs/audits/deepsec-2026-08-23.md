# DeepSec audit record — 2026-08-23

## Verdict

**NO-GO for MIN-384.** The pattern scan and a bounded AI review completed, and
a set of high-severity findings were independently confirmed. This record is not
a security clearance; the remaining review and remediation work must complete
before publication.

## Candidate and harness

- Candidate commit: `5930aa2cdec5f1caa4fe9e166b3d6eb41e65ff08`.
- DeepSec version: `2.3.6`.
- The scan used an isolated DeepSec workspace and a clean detached worktree at
  the candidate commit. This avoided unrelated generated desktop-release
  artifacts without altering them.
- A dedicated DeepSec Vercel project was linked. The link, credentials, raw
  records, and generated reports remain ignored local state.
- The selected model route is the locally logged-in Codex subscription, using
  `gpt-5.6-terra`; no API key or Vercel AI Gateway credit is required for that
  route. DeepSec 2.3.6 loads a saved Vercel OIDC token even when the
  configured route is local, so the token file was temporarily isolated for the
  successful local run and restored immediately afterward.
- Before that selection, OpenCode Zen's `x-preview-f-free` route returned
  provider network errors and the OpenRouter `stealth/ox-alpha` fallback
  stalled before it yielded an analyzable result.

## Scan coverage

The DeepSec pattern scan completed against the candidate:

- 94 applicable built-in matchers ran; 104 framework-inapplicable matchers
  were skipped.
- 1,325 source files had candidates, totalling 4,206 matcher hits.
- The TypeScript scan covered 1,599 files and the JavaScript scan covered 88.
- Priority review paths cover API and auth routes, public feedback and sharing
  paths, server boundaries, Supabase migrations, Electron code, and release
  scripts.
- `generated-matchers.ts` remains empty. No hand-authored matcher was added,
  because DeepSec's setup inventory did not produce a validated missed ingress
  family.
- Two hundred ninety-eight high-risk files were processed in bounded local passes. To reduce
  subscription usage, every batch processed one file with `medium` reasoning
  and eight maximum turns. The resulting two waves used approximately 497,000
  tokens, or about 62,000 per file on average, compared with about 97,000 for
  the initial `high`-reasoning, 20-turn probe. The subsequent 20-file wave
  used approximately 1.5 million tokens.

## Confirmed findings

Fifty-two high-severity findings and five critical-severity findings were
independently revalidated as true positives by a second `gpt-5.6-terra` pass.
The list below records the initial confirmed groups; later batches extended the
same groups and added tracked findings for CI supply chain, feedback-RPC access,
account import, push delivery, and MFA assurance:

- `lib/server/agent/command-guard.ts`: shell expansion bypasses protected
  Git-command checks.
- `lib/server/agent/network-policy.ts`: unrestricted sandbox egress enables
  exfiltration of the write-scoped forge credential in the clone remote.
- `lib/server/agent/repo-access.ts`: a GitLab account-wide API token is exposed
  to the untrusted agent sandbox.
- `lib/server/agent/control-plane.ts`: active runs retain project and repository
  authority after the initiating member loses access.
- `lib/server/agent/repo-host.ts`: a local background-job tool grants an agent
  unrestricted host-shell execution.
- `lib/server/agent/self-hosted-sandbox.ts`: the self-hosted LLM relay follows
  attacker-controlled redirects to private services.
- `lib/server/agent/vm/supervisor.ts`: pull-request head files can be injected
  into privileged agent instructions.
- `lib/server/agent/vm/supervisor.ts`: local agent runs can receive
  prompt-controlled arbitrary filesystem and network access.
- `lib/server/agent/models-catalog.ts`: generic BYOK model discovery follows
  redirects and loses DNS pinning.
- `app/api/git/github/setup/route.ts`: a relay claim callback can accept an
  installation identifier that is not bound to the intended pending setup.
- `lib/server/agent/diagnostics.ts`: repository-controlled diagnostics can be
  interpolated into a privileged agent context.
- `lib/server/agent/tools.ts`: agent retrieval of user-controlled link resources
  does not enforce the outbound-network policy.
- `app/api/relay/webhook-secret/route.ts`: webhook endpoints can target
  cloud-provider internal services.
- `app/api/webhooks/gitlab/route.ts`: webhook repository names are not bound to
  authenticated repository identifiers, and a global legacy secret remains
  valid across repositories after rotation.
- `lib/server/agent/background.ts`: a textual command check is bypassed by shell
  indirection before a background job executes the command through `sh -c`.
- `app/api/cron/forge-relay-deliveries/route.ts`: scheduled relay fan-out can
  issue attacker-directed requests to internal services because delivery does
  not validate or pin the stored webhook destination.
- `app/api/admin/forge-relay/instances/[id]/route.ts`: revoked relay instances
  can continue receiving queued webhook payloads.
- `components/auth/reset-password-form.tsx`: password-reset MFA is enforced only
  by the client.
- `lib/server/agent/byok-validate.ts` and `lib/server/agent/model.ts`: BYOK probe
  and runtime requests lose DNS pinning and accept unsafe redirects.
- `lib/server/agent/launch.ts`: issue-controlled context can drive a local agent
  with filesystem and network authority.
- `components/settings/byok-connect-panel.tsx` and `lib/server/assistant/loop.ts`:
  BYOK endpoints can trigger redirect-following, unpinned server-side requests.
- `lib/server/agent/vm/opencode-permissions.ts` and `private-address.ts`: local
  VM permissions, IPv6 classification, and DNS pinning can be bypassed.
- `lib/server/agent/plan-review.ts`: repository package-script names are inserted
  into an instruction-bearing agent prompt.

One initial critical-severity candidate was a false positive after independent
Terra and Sol revalidation: endpoint registration validates public HTTPS
destinations, and delivery retains TLS hostname verification without following
redirects. Twenty-eight medium-severity, two high-bug-severity, and ten
bug-severity candidates remain
unvalidated, including premature consumption of an OAuth authorization code
before PKCE validation and repeated synchronous `scrypt` decryption on
unauthenticated public-board requests.

## Incomplete phases and residual risk

DeepSec's setup-only threat-model response was malformed JSON after reading the
repository, so it could not write a validated surface inventory. A focused
investigation of ten highest-risk files was then started with the configured
OpenRouter fallback route. Its first batch stalled at the provider and was
stopped after the process reported an error.

An earlier local Codex attempt returned HTTP 429 after DeepSec retried the
request. The successful Terra pass showed that the root cause was instead
DeepSec loading its saved Vercel OIDC token and silently sending requests to
Vercel AI Gateway. Further runs must keep that token unavailable to the process
and use small sequential batches: one file can consume roughly 100,000 tokens.

The fifty-two confirmed high-severity findings and five confirmed critical
findings are not remediated. Full-model review was paused after 298 files
because the remaining 1,027 candidates would require disproportionate
subscription usage. The remaining work uses static, dependency, configuration,
and permission-boundary checks, with model revalidation reserved for high-signal
results; all linked remediation issues must complete before changing this verdict.
