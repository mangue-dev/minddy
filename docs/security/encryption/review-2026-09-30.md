# Local full-stack encryption review — 2026-09-30

Reviewed PR #289 on `work/min-591-data-encryption`, starting at
`44777947fd76da22b27946636338026193ae3f4e`. This review used synthetic data,
fresh local containers, actual Supabase Auth/PostgREST/Storage services, and
the Next.js application. No production deployment or production data was used.

## Findings and fixes

1. Supabase CLI reconciles declarative buckets after migrations and on restart.
   The local configuration reopened `forge-attachments` and reduced its size
   limit. It could also reopen project icons after private activation. Keep
   forge storage private at 32 MiB and let migrations/the reconciler manage
   project icon visibility. A fresh second stack and the bootstrap regression
   verify the configuration and the reconciler's preservation of activation.
2. The guest feedback draft store invoked native browser `fetch` as a method
   of the store. Chrome rejected this with `Illegal invocation`, preventing
   persistence and recovery. Call it with the browser global receiver. The
   regression reproduces the receiver requirement; Chrome now seals the draft
   and restores it after reload without storing its text in localStorage.
3. Project, page, view and saved bookmark guards incremented content revisions
   when recording backfill attempts. The workers consequently rejected their
   own subsequent compare-and-swap writes. Preserve revisions for maintenance
   progress-only updates, excluding the page's generated search field from
   comparison because PostgreSQL computes it after BEFORE triggers. Real edits
   still increment revisions; stale content writes and stale attempt proofs
   remain rejected. Migration `20270109200008` and a PostgreSQL regression cover
   all four guards. SQL inventories and migration hashes are refreshed.

encryption and its bounded maintenance workers. Domain-specific encryption,
cleanup and scrub flags are retired, including for invitations. Explicitly
setting an old flag to `false` no longer disables that domain. The centralized
configuration check is enforced by the encrypted-column access guard.

downgrades when the global switch is paused. No SQL migration changed.

## Follow-up: private production-backup rehearsal

The release preparation also restored a private, checksummed production backup

The old Supabase Vault recovery root was saved and verified in macOS Keychain,
separately from the application encryption root. The rehearsal uses a synthetic
application root. Private backups and credentials remain outside Git.

The real historical rows exposed these additional defects:

- The recorded Numo view migration did not match the historical view columns.
  Reconcile that specific drift before adding encrypted projections. Preserve
  current views and ACLs, and roll back if an unexpected dependency exists.
- Backfill progress compared vectors without a valid operator search path.
  Compare their serialized values instead. Coupled Agent run/runtime updates
  must update the existing guarded row without replaying the plaintext insert
  path; branch synchronization must ignore unchanged maintenance fields.
- Personal Numo conversations legitimately delegated into the actor's project.
  Resolve that explicit ownership without accepting another actor's run.
- JSONB changes object property order. Verify delegation and worker payloads
  with structural equality instead of serialized-string equality.
- Project, page, view and bookmark backfills need a service-only verified CAS
  RPC to preserve revisions and edit timestamps. Reload the REST schema cache
  after creating it. Icon verification must use the same maintenance context.
- Agent and Numo workers shared parent-row locks and deadlocked when run in
  parallel. Serialize those related passes; failed jobs must not prevent later
  passes from running. Other domain workers retain their existing scheduling.
- A legacy Forge object was incorrectly considered orphaned while its project
  link and PR used different identity formats. Preserve objects while their PR
  or legacy alias exists. The rehearsal recovered two affected test objects
  from the original backup and verified their bytes after conversion.
- Page search excerpts must match the actual PostgreSQL token classes observed
  in this corpus, including HTML, compounds and short UTF-8 words. Break score
  and edit-date ties by ID. Bound Markdown, rank and excerpt caching by bytes,
  entry count and expiry; recheck authorization and authenticated decryption
  before using cached results.
- Initializing page encryption metadata updated every historical edit date.
  The migration is pending in production; suspend only the timestamp trigger
  for that initialization and restore it within the same transaction. A real
  PostgreSQL regression proves ordinary edits and failure rollback remain safe.
