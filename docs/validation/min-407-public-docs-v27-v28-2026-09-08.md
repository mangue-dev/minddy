## Chosen deployment and required inputs

I choose **full**, on a disposable Linux VM with its own browser at `http://localhost`, filesystem Storage, and a disposable local Mailpit inbox. I want an independently operated, free local rehearsal without a pre-existing Supabase Cloud account. Managed mode is unsuitable for this particular rehearsal because it requires an already provisioned compatible project and provider-controlled backup/restore access. It remains a supported lower-memory option for operators who already have that service. The desktop-local minimal profile is a distinct topology and is not substituted for full-profile acceptance.

The operator owns the host, Docker daemon, capacity, application and Supabase configuration, account administration, email, optional provider accounts, firewall/TLS for eventual public use, monitoring, backup retention, off-host copy, restore drills and update decisions. The release supplies the application/migrations, exact Supabase compatibility pin, Compose profiles, bootstrap/doctor and operation instructions. PostgreSQL alone is insufficient. Scheduler and agent runner are core reference services; AI provider usage remains optional. Use `--no-forge-relay` for the isolated rehearsal.

Inputs: Linux amd64 or arm64; Node 24; pnpm 10.28.0; Docker Engine ≥27 and Compose ≥2.29; Git, curl, Cosign, Supabase CLI, PostgreSQL clients; GNU tar/find/sort/checksum tools for the Linux cold-backup commands; permission to run Docker and sudo tar; at least 8 GB RAM/4 CPUs/60 GB SSD for same-host full mode, preferably 16 GB/6 CPUs/100 GB; two immutable release refs and image digests; empty upstream destination; source/target/environment/report paths; encrypted backup destination outside active data; a fresh restore host of the same architecture or sequential unused directories/volumes; an application origin and disposable admin address. Full mode generates API and encryption secrets; retain them privately. The upstream pin is `self-hosted/v0.7.2`, commit `549db119c44c25167461812041ba198bde2b31a4`.

Production additionally needs operator SMTP settings, reachable approved origins, and DNS/TLS for public access. A private LAN client must use the server's private IPv4 address, not its own localhost. Managed mode instead requests Supabase API URL, anon key, service-role key and a migration-capable database connection. No real value for any credential was collected.
