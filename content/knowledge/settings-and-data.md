Project owners manage project settings, members, categories, recurrences, the linked Git repository, import, integrations, and feedback boards. Account settings belong only to the current user and include identity, interface language, personal preferences, notifications, AI providers and the default Numo model. From their profile, users pick a generated avatar or upload their own image, and the avatar follows them across projects, comments, and conversations. A project member can work on issues and categories according to the available product permissions, but cannot change owner-only settings.

Numo can change most of these settings on request. Project-side, `update_project` covers name, key and accent color, auto-assign on create, Smart Assign and its per-member rules, Smart Triage's static rules engine, the feedback AI review and translation options. Account-side, `update_account_settings` covers the display name, interface language, display theme, the keyboard send shortcut, where Numo-created issues land, auto-assign and Smart Fill preferences (including whether Smart Fill links related issues, `smart_fill_relations`), whether the user's issues are indexed as private vectors (`issue_indexing`), the personal cycle knobs, the Inbox notification toggles, whether copying an issue's prompt starts it, and analytics consent. Project automations and account presets are retired. The owner opens Routines to review idempotent paused proposals that retain original rules, effort filters, delays and human checkpoints; enabling them is explicit. Pending and human-waiting old chains stop. Account settings → AI holds the Minddy AI providers used by Numo, routines, automations, voice and feedback. Several API providers can remain connected; capability routing selects one compatible provider per family, and usage switches determine which features use its key. The default Numo model is saved per user and provider: App default or a specific available model. An explicit conversation model overrides it; a conversation following the default picks up later changes, while an admitted turn keeps its frozen model. Settings that Numo can explain but never change: the personal Numo model default (Account settings → AI only) and the credentials themselves: AI provider keys, GitHub or GitLab connections, two-factor authentication, and the avatar file, which stay user-driven.

minddy does not sell data or use it for advertising. The Data section of account settings lets users download a JSON transfer file and restore it on another minddy instance. The transfer is additive and preserves project, issue, page, and personal-data IDs whenever the destination can safely reuse them; conflicts receive new IDs and are reported after import. Project memberships are restored only when the referenced project already exists on the destination. Personal Numo model preferences are included and rebound to the importing account, without provider credentials. Passwords, API keys, OAuth tokens, repository credentials, and billing subscriptions are never transferred. Repository access tokens are encrypted before storage and are used only when a user triggers an action that needs the connected repository.
