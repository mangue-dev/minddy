Projects hold a team's issues, members, categories, saved views, pages, integrations, and feedback board. An issue is one discrete piece of work. It has a title and can also carry a description, status, priority, effort, assignee, objective, categories, a due date, recurrence, linked issues (including blocking dependencies), sub-issues, comments, resources, and an implementation plan.

Issue and objective descriptions, comments, the creation dialogs and the task notebook use the same editor as project pages; the notebook also has the pages' block handles and + button, the other surfaces do not. Selecting text shows the formatting toolbar (bold, italic, strikethrough, code, link) everywhere, and images can be pasted or dropped into descriptions and the notebook; other kinds of files remain a page feature. Everywhere, "/" inserts headings, lists, tasks, quotes, callouts, code, toggles and dividers, and "@" mentions people, issues, objectives and pages. Their text is still stored as Markdown, which Numo, MCP agents, notifications and exports read. Issue and objective descriptions are edited live together, like pages: several people type in the same description at once, with each person's caret shown in their color and name, and changes by Numo or an MCP agent appear in open editors as they are saved. The Markdown that agents and integrations read follows a couple of seconds after typing stops. Comments, the creation dialogs and the task notebook are not shared live, and version history remains a page feature.

Smart Fill is an optional account preference that fills an issue's missing priority, effort, categories, and objective. When the "Re-evaluate edited issues" preference is on, it reads an issue created with Smart Fill again five minutes after its title or description stops changing, and may update those properties, but only the ones left empty at creation and never changed by hand since; each change appears in the issue's activity (and in the objectives' activity when the objective moves) under Smart-fill. It also, after the issue is saved, links it to related issues in the same project (related, blocks, or blocked by). It runs in the background, adds at most three relations per pass, abstains when unsure, never touches a pair that already has a relation, and never re-adds a link someone removed. Its links appear in the issue's relations and timeline under Smart-fill and are removed like any relation. The separate "Index issues" preference controls whether issue titles and descriptions become encrypted vectors used to find candidates; when off, candidates are found by shared words only.

Issue search is hybrid. Text matches and exact identifiers (such as MIN-42, #42 or 42) always come first and are never displaced. When the query reads like a description (at least two words, or one word of six letters or more), the command palette, @ mentions in descriptions, pages, comments and Numo, the relation pickers, the triage "Mark as duplicate…" picker, a pull request's "Link an issue", Numo's "Add context" → "Issue" menu and feedback's "Link to an existing issue" also add, shortly after typing stops, up to five issues found by meaning under "Related by meaning". They come from the same issue index as Smart Fill, appear after the text matches without moving the highlighted row, and only include issues that picker could already offer (for example, a relation picker still offers only unlinked issues of the same project, and the palette searches up to 25 of the searcher's readable projects). Each new query costs one AI embedding call in the searcher's Automations usage, listed as "Issue search"; a repeated query is normally not billed again. Search by meaning is skipped, leaving text results only, when the searcher turned off "Index issues", when the administrator turned off Smart Fill relations, when the AI budget is exhausted or when the provider is slow or unavailable. Issues not indexed yet, or whose author turned off indexing, are found by text only. Boards and lists have filters, not a free-text search box. Every issue search uses the same order: In progress and In review issues first, then Backlog and Todo, with Triage, Done, Canceled and Duplicate issues always last; text relevance orders issues within each group, and an identifier typed in full comes first whatever its status.

Objectives group issues around one outcome and show their progress. An objective with a target date also shows a momentum signal — accelerating, steady, slowing, or stalled (with separate states for objectives not started, complete, or canceled) — computed from recently completed issues, with an estimated finish date when there is enough activity to make one meaningful. Without a target date, the momentum panel, history, pace statistics, and finish estimate are hidden; overall progress remains available. Adding a target date shows the panel again. Triage is the arrival area for work that needs review before it enters the normal board. Each user also has a personal cross-project cycle for weekly or fortnightly planning. Saved views filter and sort the board without changing the issues themselves. minddy uses statuses such as triage, backlog, todo, in progress, in review, done, canceled, and duplicate.

Saved issue and objective drafts require confirmation before deletion. Triage filters incoming tickets by priority, effort, assignee, objective, categories and integration; values within one property are alternatives and different properties are combined. Reset clears the property filters.
