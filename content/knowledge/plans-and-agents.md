An issue description explains the problem, expected behavior, constraints, and definition of done. Its implementation plan is separate. Ask Numo to inspect the linked repository before producing a code-level plan; Numo should not invent file paths, functions, components, migrations, or code snippets it has not verified.

Numo organizes and tracks work: it can write or review a plan without changing the issue's status, but it does not write code, push branches, run tests or open pull requests. Code is written by the user's own coding agent, connected to minddy through MCP. Numo can still handle pull requests directly: read one, comment in its threads, update it, or merge it. On a pull request, **Merge with Numo** has Numo write the merge commit title and description before merging, and mentioning `@numo` in a pull request comment opens a read-only review conversation; it never pushes commits. A linked pull request shows a live preview deployment when one exists. A failed turn can resume from its last saved checkpoint when that checkpoint survived. Plans use Markdown task checkboxes. In an issue's Plan tab, the plan is edited in place in the same editor as the description, live with other members, Numo and connected agents. Existing plans should be extended or patched instead of rewritten wholesale, so completed tasks and concurrent edits are preserved.

To have an issue implemented, hand it to a coding agent outside Minddy, such as Claude Code, Codex or Cursor, with Copy as prompt: generate or review a plan, implement, verify the implementation, or a custom request; several selected issues copy as one combined prompt. Copying runs no AI model. The prompt carries the issue's fields, relations, resource count and plan progress (never the plan text, which the agent reads through the Minddy MCP server or asks for), the linked repository, and every linked pull request with its state and branches when known. The agent continues an open pull request's branch, treats merged or closed ones as history, and otherwise gets a branch-name suggestion made of the issue identifier and a short title, which it adapts to the repository's own convention. Keeping the identifier in the branch, the pull request title or a "Fixes" line lets Minddy attach the pull request to the issue. When pull request information cannot be loaded, the prompt says so rather than claiming there is none. The account preference **Start the issue or task when I copy its prompt** moves a not-yet-started issue or notebook task into progress when its prompt is copied. On a pull request, **View conversations → Fix all → Copy prompt** copies the unresolved review threads as a prompt for the agent.
